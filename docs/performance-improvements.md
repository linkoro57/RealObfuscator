# Performance improvements - 2026-11-16

## Implementation

- VM descriptors and encrypted string pools are constructed as AST data, eliminating formatting/reparsing of large generated payloads. Final output validation remains enabled.
- Packed and table payload paths avoid constructing unused representations; record encoding uses fixed-size storage and preallocated vectors. Decimal escapes avoid an allocation per byte.
- Literal lookup uses indexed numeric bits and decoded string bytes, with explicit nil/boolean entries. Signed zero remains distinct. Capture-list tables retain structural comparison.
- Bodies with no closure, native method bridge or generic-iteration bridge use scalar registers instead of cell tables. Bodies observable by bridges retain cells.
- The interpreter is renamed once. Cached execution skips decoder construction after its prototype has decoded records.
- Rolling decoding reuses bounded invocation-local scratch and returns scalar operands instead of allocating instruction tables. It still decodes on every read, with record-integrity checks and current-record RLE bounds.
- Nil caching uses a private sentinel, empty internal vararg packs are shared read-only, and hot constant reads are emitted in opcode handlers. Maximum hardening keeps plaintext constant values invocation-local.
- Runtimes without generic-iteration instructions execute the dispatch loop directly; runtimes needing native iteration retain the nested execution/signal protocol.

## Matched measurements

The baseline is a saved optimized benchmark executable from before these optimizations; the final executable uses the same benchmark driver, workloads, configuration, seed and release settings. Runs were sequential on the same Windows x86-64 machine and Luau interpreter. Compiler configuration construction remains outside timed operations.

Runtime matrix: seven workloads, five profiles, size 16, seed 42, nine Rust samples with a 5 ms target, three fresh Luau processes and nine warm samples per process. Each warm invocation performs two work units. Scaling matrix: three structural workloads, three profiles, sizes 32/128/512, seed 42 and seven Rust samples. ## Limits and tradeoffs

These are local measurements rather than statistical guarantees. Unchanged original-source controls varied: their median per-workload warm timings changed by -8.8% and module-load timings by -19.4%. Some of the small compiler/native timing differences can reflect machine variation. The measured reductions are not universal speedup promises.

Inlining hot constant reads can increase interpreter source size and cold-load cost. For example, arithmetic/basic-cached generated bytes changed from 20014 to 21148. Its median module-load time changed from 3.132 to 6.066 ms across three processes. Across all seven workloads, basic-cached module-load medians changed by -3.9%; maximum-cached changed by +3.0%. Measure startup-sensitive applications separately from hot execution.

No protection preset was weakened to obtain these numbers: virtualization, opcode diversification, configured cache lifetime and integrity flags remain enabled according to the selected profile. They remain obfuscation mechanisms, not cryptographic confidentiality guarantees.

## Verification

- 38 Rust tests pass with `REQUIRE_LUAU_RUNTIME=1`, including captures, loop captures, custom iteration, coroutine yields, multiple/nil returns, signed zero, binary constants, strict fallback rules and corrupt instruction/string rejection.
- Three Python comparison tests pass; formatting and Clippy pass with warnings denied.
- An additional 1,056-case runtime validation checks all 24 workloads and 44 profiles at size 3, seed 7, against their original checksums. It uses one process/sample per case for broad correctness coverage, not precision timing.
