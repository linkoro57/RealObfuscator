# Local benchmark results - 2026-11-14

The new harness completed **1,256 compiler cases**, including **128 cases with Luau execution**, and wrote **7,400 raw timing observations** across **1,780 summary rows**. This is a selected coverage run, not a claim that all 9,504 default exhaustive cases were measured.

Environment: Windows x86-64; AMD64 Family 23 Model 160 Stepping 0, AuthenticAMD; `rustc 1.99.1 (58cf8f9c3 2026-10-13)`; local Luau executable under `tests/runtime/0.741/`. The exact interpreter fingerprint, invocation arguments, Git revision and dirty status are in each run's metadata. Builds, correctness tests and timing matrices ran in separate phases; timing matrices ran sequentially.

| Run | Cases | Parameters |
| --- | ---: | --- |
| All workload/profile pairs | 1,056 | 24 workloads x 44 profiles, scale 8, seed 42, 3 Rust samples |
| Runtime representative matrix | 128 | 16 workloads x 8 profiles, scale 8, seed 42, 5 Rust samples; 3 fresh interpreters x 5 warm samples, 1 work unit per invocation |
| Source scaling | 72 | 3 structural workloads x 3 profiles x 4 sizes x 2 seeds, 3 Rust samples |

Every run used a 1 ms target for Rust batches. Short sampling prioritizes broad coverage; increase sample counts and batch duration before making regression decisions. All generated runtime checksums matched their original modules.

## Arithmetic workload at scale 8, seed 42

Median timings from the representative runtime run. Warm execution processes one work unit. Tiny native timings are close to timer resolution; do not interpret their ratios as stable speedups.

| Profile | Compile ms | Generated bytes | Module load CPU ms | Warm execution CPU us |
| --- | ---: | ---: | ---: | ---: |
| `original` | n/a | 156 | 1.246 | 0.300 |
| `lightweight` | 0.972 | 335 | 1.278 | 0.300 |
| `native` | 0.679 | 629 | 1.501 | 0.600 |
| `vm-basic-cached-packed` | 22.508 | 20,235 | 3.745 | 26.800 |
| `vm-max-cached-packed` | 18.502 | 24,589 | 4.445 | 32.800 |
| `vm-max-rolling-packed` | 19.310 | 24,591 | 4.802 | 1268.900 |

On this small workload, incremental VM record decoding costs materially more than retained decoded records. This observation is specific to this invocation, interpreter and device; it is not a Roblox frame-time or security measurement.

## Reproduce

```sh
cargo bench --bench obfuscation --locked -- --suite full --scales 8 --seeds 42 --samples 3 --sample-ms 1 --output target/benchmarks/full-profiles-20261114
cargo bench --bench obfuscation --locked -- --suite standard --scales 8 --seeds 42 --samples 5 --sample-ms 1 --processes 3 --iterations 1 --runtime --output target/benchmarks/runtime-20261114
cargo bench --bench obfuscation --locked -- --suite full --workload unique_strings,large_block,many_functions --profile =lightweight,=native,=vm-basic-cached-packed --scales 8,32,128,512 --seeds 7,42 --samples 3 --sample-ms 1 --no-micro --output target/benchmarks/scaling-20261114
```

Choose fresh output directories when repeating these commands; the recorded directories already exist locally. Each contains `summary.csv`, `samples.csv`, `metadata.txt` and `complete.txt`. Raw artifacts are local and gitignored under `target/benchmarks/`; the tables above retain the selected results in the repository. See [the benchmark guide](benchmarks.md) for boundaries, filters and comparison commands.
